# Squeezer 互動體驗設計

## 意圖

讓 Squeezer 感覺像一個專注、可靠的影像工作台，而不是一張設定表單。使用者拖入照片後，介面要立即回應；比較與調整時能看見實際影像；處理期間持續知道正在發生什麼、還能做什麼；完成時清楚看見成果並能接續工作。

沉浸感來自操作和結果之間清楚、連續的回饋，不靠常駐動畫、音效、強制精靈步驟或裝飾性等待畫面。

## 目標

- 所有可互動控制在按下、等待、成功、停用與失敗時都有明確狀態。
- 畫面轉場幫助理解「我從哪裡來、現在在哪、如何回去」，且不丟失選取、模式和佇列狀態。
- 壓縮進度只呈現引擎確認的狀態；預估、實際、略過、取消和失敗要能區分。
- 新手能循序完成工作；熟手仍可用一個主畫面批次操作，不必每次走完引導。
- 支援滑鼠、鍵盤、VoiceOver、減少動態偏好和不同視窗尺寸。

## 非目標

- 不加入遊戲化分數、慶祝動畫、常駐音效、AI 品質判斷、雲端同步或長篇 onboarding。
- 不為每次操作增加確認對話框；只有可能造成不可逆資料損失的操作才需要確認。現有流程保留原檔，因此移除佇列項目不應被誤呈現為刪除原檔。
- 不顯示無資料支持的壓縮預估、剩餘時間或百分比。

## 核心體驗原則

1. **立即回應。** 使用者操作後先在同一個事件循環內回應按鈕或畫面狀態，再執行分析、預覽或編碼工作。較長工作顯示明確階段與可用操作。
2. **狀態說真話。** 將「準備中、壓縮中、驗證中、完成、略過、取消、失敗」分開顯示。若引擎無法提供可量測進度，顯示有界線的活動指示與當前檔名，不製造遞增百分比或 ETA。
3. **讓動態解釋變化。** 動畫只表示加入、選取、切換、處理、完成等真實事件；避免背景循環、視差、彈跳和會阻擋點擊的轉場。
4. **保留掌控感。** 加入更多檔案、移除未執行項目、查看其他檔案、取消目前工作等操作應在合理狀態下持續可用。取消一張和取消整批要語意清楚。
5. **逐步揭露。** 預設顯示品質模式與容量結果等常用資訊；檔案詳細設定、metadata、格式、尺寸和進階快捷鍵逐步展開，不讓初次使用者面對編碼器術語。

## 旅程與回饋規格

### 1. 空狀態與加入檔案

- 空狀態的拖放區有清楚標題、可點擊的選檔按鈕、支援格式與本機處理提示；整個可用區可鍵盤聚焦並啟動選檔。
- 指標拖入時，容器邊界和簡短文案變化；拖離立即還原。拖入有效檔案後，以縮圖卡片依序落位，佇列數量立即更新。進場動態短、同時最多錯開 3 張，尊重 `prefers-reduced-motion`。
- 不支援或損毀檔案顯示在佇列中並附具體原因；其他有效檔案照常加入。重複檔案不重複新增，提供輕量提示而非模態警告。
- 背景分析時先呈現檔名與可得檔案大小，再補上尺寸和格式資料；不因縮圖失敗而阻塞整批匯入。

### 2. 佇列與圖片工作台

- 佇列是持續可回到的主畫面；顯示縮圖、檔名、尺寸、原始容量、狀態與結果。已完成工作顯示輸出容量及實際節省比例；略過工作解釋原因。
- 點選一張圖片進入工作台，使用同一個視窗內的面板或明確返回佇列的檢視，不另開不必要的視窗。工作台顯示 Before / After、容量標籤、前後切換／拖曳分割線、上一張／下一張。
- 調整品質或格式的結果若尚未編碼，不得把佔位圖片偽裝成輸出。可顯示模式說明與「完成後可比較」；若之後加入真實預覽編碼，清楚標成預覽結果。
- 品質模式可套用到已選取檔案、相同格式檔案或全批；套用前顯示目標數量，完成後提供短暫撤銷入口。逐檔覆寫以標記呈現，避免批次套用時被悄悄覆蓋。
- 批次篩選、全選、逐檔品質和新增檔案是佇列工具列的一部分，不是取代旅程的另一個產品模式。

### 3. 開始處理與進度

- 主行動按鈕動詞清楚並包含工作數量，例如「壓縮 6 張」。按下後立即進入 disabled/busy 狀態並回報已收到操作；避免因雙擊重複送出。
- 處理頁面保留批次總覽和每檔狀態。當前檔案是視覺焦點，其餘檔案清楚標示排隊、完成或遇到問題。
- 每個狀態變化以文字及圖示表達；進度動畫只用於沒有精準百分比的等待。能提供可信進度時才使用百分比。檔案完成時，更新該列與已節省總量，不重排佇列造成位置跳動。
- 單檔取消按鈕標成「取消此檔」；若只能取消整批，按鈕必須直接說「取消整批」。取消時提示目前檔案正在安全收尾或清理，完成後顯示 `已取消`，不將取消當失敗。
- 若使用者切換到其他 App，工作狀態仍留在主畫面；回來後不重播已完成的轉場，也不丟失佇列。

### 4. 完成與下一步

- 完成狀態聚焦實際成果：成功數、略過數、失敗數、總容量變化。節省數為負或無法比較時不顯示正向慶祝文案。
- 單檔結果提供比較預覽、開啟輸出或在 Finder 顯示；同一輸出資料夾可提供一次「顯示全部」。
- 完成回饋以短暫色彩／圖示變化和輕量文字確認；不播放強制音效或長動畫。新一批可沿用上次設定，但不自動開始。
- 失敗項目提供可理解原因與「重試」；重試不清除原錯誤前的輸出或其他成功結果。

## 微互動規格

| 控制 | 預設 | Hover / focus | Press / loading | 成功 / 失敗 |
|---|---|---|---|---|
| 主行動按鈕 | 動作 + 數量，清楚主次 | 對比或邊界加深；鍵盤焦點輪廓 | 即時鎖定重複送出，文案轉為明確進行狀態 | 恢復可用並顯示結果區；錯誤保留佇列 |
| 品質模式 | 顯示目前模式和簡短結果取向 | 整卡可操作，focus ring 清楚 | 選取標記立即移動，說明同步更新 | 保留選取，不因檔案結果改寫選項 |
| 佇列列 | 顯示名稱、大小和狀態 | 整列可聚焦；工具按鈕有可見標籤 | 移除或取消後局部更新，不整頁閃動 | 狀態圖示與文字同步；錯誤可展開詳情 |
| Before / After 控制 | 顯示目前為原圖或輸出圖 | 游標與焦點狀態可辨 | 拖動有連續視覺回饋，鍵盤左右可微調 | 讀屏器能讀出當前比較位置和容量 |
| 通知 / inline message | 優先靠近發生位置 | 不適用 | 長工作不以 toast 假裝完成 | 成功訊息可自行消退；錯誤持續可見直到處理 |

動態建議：微互動 120–200 ms，檢視切換 180–260 ms，批次加入錯開 30–50 ms；不使用超過 350 ms 的必要性轉場。這些是設計起點，實作時依 macOS 視窗效能和 reduce-motion 測試調整。使用者偏好減少動態時，直接切換狀態並保留焦點落點。

## 輸入、可及性與失誤復原

- 所有按鈕具體命名；icon-only 按鈕須有可見 tooltip 和可及名稱。鍵盤 tab 順序跟視覺順序一致，Escape 關閉檢視並回到開啟它的控制項。
- 至少支援 Enter/Space 啟動控制、方向鍵切換品質／比較位置、Escape 返回佇列；全域快捷鍵須顯示於選單或工具提示，且不得搶走文字輸入焦點。
- 不以顏色單獨代表完成、錯誤或進度。動態狀態使用適當的 live region，但避免每個百分點都朗讀。
- 文字和控制需有可讀對比及足夠點擊區域；聚焦、選取、停用和 hover 各自可辨識。
- 失敗不清空使用者選取和模式；移除錯誤列前不刪除來源檔。清空前若有待處理工作，明確說明哪些佇列工作會被取消／移除。

## 給實作者的範圍排序

### 先做：互動基線

- 細化空狀態、拖放、佇列列、主按鈕、busy/disabled/error/success 狀態。
- 加入局部動態、可靠的進度回饋、鍵盤焦點復原和減少動態支援。
- 在完成結果中提供單檔預覽及 Finder 顯示入口（若輸出路徑已存在）。
- 改善現有前後預覽對話框的開啟、關閉、焦點和狀態回饋；本階段不改造成新的比較工作台。
- 首階段驗收只要求目前已存在操作的完整互動品質，不以新工作台、逐檔品質覆寫或新篩選器作為交付門檻。

### 下一步：工作台與批次控制

- 單張影像比較檢視、上一張／下一張、品質套用到所選／格式／全批、逐檔覆寫標記及撤銷。
- 批次篩選和快捷鍵；不讓這些控制阻塞批次處理。

### 後續再做

- 保存預設、選擇輸出資料夾／命名、尺寸調整、更多圖片格式。
- 影片工作台、硬體編碼、資料夾監控與背景通知；先有圖片版互動基線再擴充。

## 驗收條件

### 第一階段：現有流程互動打磨

1. 主要操作有可辨識的 idle、hover/focus、pressed、busy、success、error 或 disabled 表現；不只靠顏色區分。
2. 混合有效與無效圖片拖放時，有效檔案可繼續加入佇列，錯誤定位到單檔且不阻塞整頁。
3. 壓縮期間的狀態、百分比與 ETA 都有後端資料支持；無法量測時不偽造數值。
4. 開啟及關閉現有預覽不遺失工作狀態；完成後能查看真實輸出，並在 Finder 定位。
5. 鍵盤可完成加入、切換品質模式、預覽、開始／取消及離開預覽；關閉檢視後焦點回到原控制項。
6. `prefers-reduced-motion` 下操作仍可理解且不依賴動畫。
7. 熟手可在主畫面完成加入到開始處理，不被強迫走多頁 onboarding。

### 第二階段：圖片工作台與批次控制

1. Before / After 比較可用滑鼠拖曳與鍵盤調整，且容量標籤不會把估算冒充實際輸出。
2. 可對所選圖片、相同格式圖片或全批套用品質，並辨識逐檔覆寫；批次套用有可撤銷回饋。
3. 在佇列、工作台間往返會保留選取、模式與滾動位置；上一張／下一張切換不重置比較狀態。
4. 篩選、批次選取與快捷鍵不會阻塞已開始的工作。

## 仍留給實作者的選擇

- React 元件如何拆分、動畫使用 CSS 或現有工具、資料模型如何保存選取和覆寫狀態。
- 先將圖片工作台做成 side panel 或同頁檢視；需在目前 Tauri 視窗尺寸驗證後決定。
- 真實壓縮前預覽是否值得引入額外編碼成本；沒有可靠預覽就只顯示模式說明，不可造假。
