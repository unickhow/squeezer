# Squeezer 原生批次工作區設計

## 意圖

將 Squeezer 從長頁式、偏網站的影像壓縮介面，整理成一個專注的 macOS 批次工作區。使用者開啟 App 後能立即加入和整理圖片；清單中直接看縮圖與檔案狀態；選取圖片時在同一視窗檢視內容和設定；壓縮後以實際輸出確認成果。

這個方向以使用者選定的 A「原生檔案工作台」為基礎，參考 Compresto 的內容優先、清楚批次清單和收斂的操作層次。參考其設計原則與操作密度，不複製品牌、版面細節或 Liquid Glass 外觀。

## 背景與目前狀態

- 目前 App 使用 React 19、TypeScript、Tauri 2 和 Rust；視窗預設 1120 × 780，最低 800 × 600。
- `src/App.tsx` 已有原生選檔與拖放、JPEG/PNG 佇列、縮圖、品質模式、PNG 有損開關、處理狀態、完成結果、預覽對話框和 Finder 顯示。
- 目前主畫面是品牌介紹、拖放區、清單和壓縮設定依序向下排列，視覺像一張可捲動的網頁；清單縮圖目前是預覽按鈕中的小圖，文字和操作控制偏小。
- Rust 的 `start_jobs` 目前接收一份 `CompressionOptions` 套用到整批；單檔覆寫尚不存在。設計稿中的單張設定若保留為可操作功能，前端和 Rust 任務介面都需支援逐檔設定。
- 已有互動規格 `docs/superpowers/specs/2026-10-20-squeezer-interaction-design.md` 描述啟動動效、真實工作狀態、預覽焦點回復、錯誤復原與減少動態。本設計將這些要求套用到新的工作區，不覆蓋既有資料安全規則。
- 本次確認將原互動規格「下一步：工作台與批次控制」中的工作台、搜尋與逐檔品質覆寫提升為本次交付範圍。原規格中「先做互動基線」的驗收條件仍適用，但不再代表本次交付的完整範圍；本文件的工作區與批次控制規則優先。

## 目標

1. 讓清單、縮圖和每個檔案的處理狀態成為主要視覺焦點；不需要逐張打開就能辨認檔案。
2. 將主要操作、批次品質選擇、選取圖片的詳細資訊放進單一原生視窗，減少上下捲動和跨頁切換。
3. 讓滑鼠、鍵盤和拖放操作都有即時、靠近操作來源的回饋；處理中保留檔案順序、選取和焦點。
4. 使用繁體中文的短句、清楚動詞與一致的狀態詞彙，讓每個按鈕和錯誤訊息都能說明結果或下一步。
5. 保留本機處理、原圖不覆寫、結果只根據實際輸出呈現，以及使用者已確認的 1–2 秒短啟動動效。

## 非目標與反目標

- 不新增影片壓縮、格式轉換、資料夾監控、雲端同步、帳號、歷史瀏覽器或多工作區。
- 不複製 Compresto 的品牌、精確像素尺寸、圖示或視覺材質。
- 不使用長頁式介紹作為進入 App 後的主要內容；不加入常駐動畫、裝飾性圖表、音效、誇張慶祝或強制 onboarding。
- 不以估算容量、虛構進度或 ETA 冒充真實結果。
- 不將移除清單項目表述成刪除原始檔；壓縮輸出不得覆寫來源。

## 設計方向

### 視窗結構

- 使用 macOS 標準視窗標題列與交通燈控制。工作區填滿視窗，不保留大型品牌標語或獨立網站式首頁。
- 主區域由工具列、批次清單和底部批次品質列組成；選取檔案後，右側檢視器顯示圖片預覽及詳細資訊。
- 不保留固定的格式分類側欄。批次數量和目前狀態靠近清單標題；搜尋、加入、移除等操作靠近清單。
- 搜尋以檔名和來源資料夾名稱做不分大小寫的包含比對，只篩選畫面列，不修改底層佇列、狀態或執行工作。沒有符合項目時顯示「找不到符合的照片」和清除搜尋動作；搜尋中的選取項目被篩掉時，清除該選取並在檢視器顯示選取提示；清除搜尋後可重新選取完整清單。
- 主清單在視窗可用寬度內顯示縮圖、檔名、格式／來源位置、尺寸、原始容量、狀態和必要列操作。縮圖在清單中直接可見，點擊可開啟較大的前後比較預覽。
- 預設選取佇列中的第一個可操作檔案；沒有選取時，檢視器提供簡短引導，選取時保留明確焦點樣式。
- 選取圖片的檢視器顯示較大原圖預覽、檔名、格式、像素尺寸、原始容量及該檔品質設定。沒有真正輸出前不得模擬 After 圖或顯示容量預估；完成後才顯示實際輸出和節省量。
- 視窗縮至最低寬度時，檢視器可收合或轉為同視窗檢視面板；清單至少保留縮圖、檔名、容量和狀態，不裁切主行動按鈕。不得透過縮小字體解決窄版面。

### 批次品質和逐檔設定

- 底部控制列保留四個品質選項，以繁體中文命名：`無損`、`高畫質`、`平衡`、`小檔案`。切換後立即顯示目前選取，並更新清楚的一句設定說明。
- 批次品質預設作用於所有未自訂的待處理檔案；使用者在檢視器中調整單張時，該檔標示為「個別設定」，不默默被批次變更覆蓋。檢視器提供「沿用整批」以清除該檔覆寫。
- 批次品質變更不改寫已完成檔案的結果，也不會在處理中的任務上途變更 encoder 參數。處理中使用者可調整下一批設定，並清楚看到此設定會套用於待處理項目。
- 單張設定沿用既有品質模式和 PNG 有損選項，不新增自訂品質滑桿、格式轉換或未規劃的輸出參數。個別覆寫只可套用到尚未開始的工作；分析中／處理中／已完成的檔案設定鎖定，主批次設定可供下一批待處理檔案使用。
- `無損` 對 JPEG 仍是略過重新編碼；PNG 採用無損最佳化。任何模式下 PNG 有損色彩縮減維持獨立、預設關閉，並明說最多 256 色和可能的視覺差異。

### 主要旅程

```text
啟動（主畫面立即可用，短品牌動效不阻擋操作）
  → 使用原生選檔或拖入多張圖片
  → 清單立即列出檔名和可取得容量，分析完成後補上縮圖／尺寸
  → 清單選取圖片，在右側檢視原圖及檔案資料
  → 設定整批品質；必要時為單張覆寫
  → 開始壓縮，佇列逐項顯示真實階段和結果
  → 點擊縮圖查看實際 Before / After，或在 Finder 顯示輸出
  → 加入下一批，沿用品質設定但不自動開始
```

### 空狀態與匯入

- 空清單使用工作區內的簡潔拖放引導，提供可見的「加入照片」按鈕、支援格式與本機處理說明。
- 拖入時只高亮清單承接區並說明可放開加入；離開時還原。選檔按鈕和拖放走同一匯入流程。
- 匯入後立即建立檔案列；分析、縮圖失敗或不支援格式等問題附在對應檔案，不阻塞其他有效檔案。
- 重複項目不重複新增，使用短暫、非模態訊息說明。錯誤訊息保留至使用者可見或採取動作。

### 清單、選取和預覽

- 點擊檔案列選取並更新右側檢視器；點擊縮圖／預覽控制開啟現有的大圖前後比較對話框。點擊預覽不可意外開始壓縮。
- 檔案順序依加入順序保留。分析、完成、失敗和移除均以就地更新，不重排、不閃爍整份清單。
- 活動列以狀態文字、圖示和輕量側線表達分析中、壓縮中、驗證中；終態區分完成、略過、失敗與取消，不能只靠色彩。
- 完成列顯示實際輸出大小和實際節省比例；略過列顯示可理解原因。失敗列有原因和重試動作。Finder 顯示只對已有輸出的檔案可用。
- 清單支援鍵盤上下移動選取；左右欄位資訊由讀屏器按檔案名稱、尺寸、容量、狀態順序讀出。移除或關閉檢視後焦點移至合理的相鄰控制。搜尋欄支援 Escape 清除目前字串；篩選不更改鍵盤佇列順序。

### 處理和結果

- 主行動按鈕顯示動作及待處理數，例如「壓縮 4 張照片」。空佇列時停用並說明先加入照片；按下後立即鎖定重複提交並回報已開始的項目數。
- Rust 任務狀態仍是進度唯一真相。無可信進度值時用不定活動指示和當前階段，不顯示虛構百分比或 ETA。
- 可在處理中加入下一批和檢視其他檔案。批次品質變更只影響尚未開始的檔案；取消與移除仍遵守現有安全收尾規則。
- 所有完成訊息以實際成功、略過、失敗、取消數和輸出 bytes 為依據。無節省或無法比較時不顯示正向節省提示。

## 互動、轉場與操作回饋

- 啟動時短暫顯示品牌標記接續主工作區，總長約 1–2 秒；首繪即能操作，不使用阻塞式開場頁，也不在每次狀態更新重播。
- 按鈕、品質選項、檔案列、縮圖、搜尋欄和面板都有 idle、hover、focus、pressed、busy、disabled 等適用狀態；鍵盤焦點清楚可見。
- 加入檔案後只對最多前三列做輕微錯開落位，其餘立即出現；分析和處理狀態就地更新，行動不等待動畫。
- 選取列和檢視器使用短促淡入／邊界變化說明對應關係；大圖預覽採用簡短、可關閉的面板轉場，Escape 關閉後焦點回到原縮圖按鈕。
- 成功、失敗、移除和批次開始回饋靠近觸發位置；短暫提示不承擔長工作進度，也不蓋住清單。
- 支援 `prefers-reduced-motion`：移除位移和逐列延遲，保留即時視覺狀態、焦點與文案。

## 文案與視覺語言

- 面向使用者的產品介面使用繁體中文。使用短動詞和一致詞彙：`加入照片`、`移除`、`壓縮`、`檢視原圖`、`檢視輸出`、`在 Finder 顯示`、`等待中`、`分析中`、`壓縮中`、`驗證中`、`已完成`、`已略過`、`失敗`、`已取消`。
- 品質名稱固定為繁中，避免混用 `Lossless`、`High quality` 等介面英文。副檔名、必要格式名稱及技術設定名稱可以保留原文。
- 文字尺寸以目前 1120 × 780 視窗為基準，清單主要文字至少 13 px、次要資料至少 11 px、狀態不低於 12 px；不為塞入更多欄位縮小到難讀。
- 表面採淺色中性 macOS 材質、細緻分隔線和節制層次；主要內容保持高對比。避免大面積裝飾漸層、宣傳式標語、厚重卡片牆和純裝飾性玻璃模糊。
- 色彩需兼顧淺色背景的文字對比；互動選取、成功、警告與錯誤均有圖示／文字，而非只用色彩區分。

## 可及性、縮放與輸入

- 保留原生按鈕語意；所有 icon-only 控制有可見 tooltip 和可及名稱。工具列與清單依視覺順序安排 Tab 順序，Enter／Space 可啟動，Escape 可收起檢視器或關閉比較預覽。
- 支援 VoiceOver 讀取動態列狀態；對整批結果使用精簡 live region，不逐筆高頻宣讀活動百分比。
- 視窗支援現有 800 × 600 最低尺寸。窄視窗折疊檢視器，但維持清單關鍵資訊與主行動按鈕的可見性；內容區可捲動，標題列和主要動作維持可達。
- 鍵盤焦點、選取、錯誤、成功和停用狀態均需有非顏色識別；操作控制點擊面積以 24 × 24 CSS px 為底線，常用主操作盡量達 32 × 32 CSS px。

## 安全與資料規則

- 本機處理提示只在事實允許時顯示；不新增任何上傳、帳號或雲端依賴。
- 永遠保留來源檔，不把「移除」或「清空清單」描述成刪除檔案。
- 前後比較只能用真實輸出；輸出未產生時只顯示來源圖和模式說明。
- 逐檔品質覆寫需與 Rust 端該任務使用的實際 `CompressionOptions` 一致，不能只改前端顯示。

## 驗收條件

1. 進入 App 後不再先看到大幅品牌介紹和縱向表單；1120 × 780 下工作區、清單和選取檢視器一屏可用。
2. 清單每筆都能直接看到縮圖、檔名、尺寸、原始大小和文字狀態；點列更新檢視器，點縮圖可放大檢視。
3. 加入檔案、拖放、搜尋、逐筆移除、批次品質選擇、逐檔覆寫、開始、取消、失敗重試和 Finder 顯示各有明確回饋，且不丟失清單順序。
4. 搜尋只比對檔名與來源資料夾，清除搜尋可回到完整佇列；篩選不會移除檔案、停止工作或改變其狀態。
5. 批次品質更新只套用至未自訂且尚未開始的工作；逐檔覆寫在清單可辨識，後端壓縮結果使用該覆寫設定，且能恢復沿用整批。
6. 處理狀態、輸出容量和節省量完全依實際後端事件；輸出不存在時不顯示模擬 Before / After 或估算容量。
7. 原生選檔器、拖放和預覽錯誤不清空有效檔案；單一檔案錯誤不阻塞同批其他檔案。
8. 啟動動效持續約 1–2 秒且不阻擋操作；減少動態設定下不播放位移或逐列延遲。
9. 視窗縮至 800 × 600 時仍可新增、選取、開始處理和看見狀態；主要與次要文字維持上述最小字級。
10. 鍵盤可完成加入、清單選取、搜尋、品質切換、單張覆寫、預覽開關、壓縮與取消；關閉預覽後焦點回到開啟位置。
11. 主要操作和狀態使用一致繁體中文，沒有網頁宣傳文案、孤立英文品質名稱或只靠顏色的狀態提示。

## 由實作者決定

- React 版面如何拆分元件和哪些面板狀態需要保存；只在有明確重用或測試價值時抽離元件。
- 逐檔覆寫在 Tauri command 和 Rust 任務資料模型中的最小相容表示；不得改變全域批次設定已確認的語意。
- 800 × 600 下檢視器折疊／展開的精確斷點與動畫實作，需以真實視窗手動確認字級、焦點和主操作可見性。
- 現有啟動動畫的具體 easing 與時序，只要保持 1–2 秒、不阻塞輸入且符合減少動態偏好即可。
